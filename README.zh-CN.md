# FreePort · 自由港

**你的 C 盘，不该替所有默认设置买单。**

**把数据搬走，把工作环境留下。**

[English](README.md) · **简体中文**

Windows 目录迁移与恢复工具。选好目录和去处，一键开始迁移；想搬回来，一键开始恢复。数据换个地方，软件继续通过原路径访问。

> **状态：开发预览。** 当前目标是核心迁移/恢复投产可用，尚未发布可用于真实数据的稳定版；投产验收条件见[需求](docs/requirements.md)第 8 节，当前进度见[实现状态](docs/implementation-status.md)。

## 「我明明把软件装在 D 盘，怎么 C 盘又满了？」

装软件时，我特意选了 D 盘。项目放在别的盘，下载目录也改了，回收站刚清空。

C 盘还是红了。

AI 工具又下载了一个模型，编辑器又装了几个扩展，编译器攒了一轮缓存，包管理器又留了一份依赖。它们藏在 `AppData`，藏在用户目录里那些点开头的文件夹，平时谁也不会去看。

直到某天，系统更新失败，项目编译到一半报错，模型下载到最后提示空间不足。工作还没做完，你得先到处找：还有什么能删？

再看看旁边的 D 盘、E 盘，明明还空着一大截。

**电脑有空间，软件却总往同一个地方塞。**

这就是我想做 FreePort 的原因。

## 你不该为了挪个文件夹，先读二十篇教程

安装时一路点「下一步」，很正常。看到不认识的目录不敢乱动，也很正常。

如果你是新手，`AppData`、隐藏目录、环境变量这些词，足以让一个空间问题变成一道技术门槛。你只是想腾点地方，又怕一挪就打不开软件。

如果你是老手，你可能会改缓存路径，会写 `mklink`，也知道怎么建目录联接。但找目录、查占用、搬数据、做校验、记住每个目录搬去了哪里，仍然得自己来。换个工具，再来一遍。

**大家犹豫的，其实都是同一句话：「搬完以后，还能正常用吗？」**

FreePort 希望把发现、预览、迁移和恢复放进同一个流程，让你动手之前，就能看清准备搬什么、搬去哪里、遇到了什么问题。

## 给数据换个家，把原来的门牌留下

FreePort 的思路很直接：把选中的目录迁到你指定的位置，再在原位置留下一个目录联接（junction）。软件沿着原路径访问，就能到达新的位置。

比如：

| | 软件访问的路径 | 数据实际存放的位置 |
| --- | --- | --- |
| 迁移前 | `C:\Users\You\.cache\huggingface` | C 盘 |
| 迁移后 | 原路径不变，成为目录联接 | `D:\Dev\huggingface` |

你决定数据住在哪里，软件继续认原来的地址。迁移流程保留原路径，无需逐个改写软件配置和环境变量。

C 盘是最常见的痛点，你也可以选择其他受支持的本地 NTFS 盘。若只是同一个盘内换个文件夹，该盘的可用空间不会因此增加。

## 选好，一键搬；需要时，再搬回来

图形界面的目标流程很简单：

1. **选盘扫描。** 看有哪些候选目录、位于哪里、占用多少空间，以及哪些不能搬、为什么。
2. **勾选目录，选择去处。** 候选默认不勾选；确认每一项「原路径 → 目标路径」。
3. **点击迁移。** 完成复制和校验，再切换原路径、建立连接，逐项显示结果。
4. **需要时恢复。** 扫描连接所在的盘，选中连接，确认所需空间，把当前位置恢复成真实目录。

**「一键」是选好、看清之后，一次开始执行。** 大目录的搬运和完整校验需要时间，FreePort 希望省下的是你反复查教程、敲命令和核对路径的精力。

新手可以在图形界面里看清再选；老手可以用 CLI `fp`，两者共用同一核心与校验流程。

## 关注那些总在悄悄长大的目录

规则与发现机制围绕真实的空间压力设计：

| 总在变大的内容 | 计划覆盖的例子 |
| --- | --- |
| AI 工具与本地模型 | Cursor、Claude Code、Kimi Code、Hugging Face、Ollama、Torch、ModelScope |
| 编译与构建数据 | Go 缓存、Cargo 缓存、vcpkg 下载与构建目录、C++ 编译缓存 |
| 包管理器缓存 | npm、pip、uv、pnpm、NuGet、Gradle |
| 编辑器扩展 | VS Code、Cursor、Obsidian 插件 |
| 应用数据 | 企业微信数据、文件与缓存，与其他无关目录分别识别 |

这些是发现目标，不表示所有版本、所有目录都已通过迁移验证。名字相同只是线索，真正操作前仍须核验实际路径、内容、连接、权限与占用。受保护的系统位置和不支持的对象必须明确阻塞，并说明原因。

## 「以后想搬回来，怎么办？」

恢复从一开始就是产品的一部分。

比如模型缓存实际放在 D 盘，C 盘留下了连接。后来你想把数据搬回 C 盘，就扫描 C 盘，查看连接指向哪里、恢复需要多少空间，再确认恢复。

**搬回来的是当时的最新内容**，包括迁移之后新增、修改的文件。这是改变存放位置；备份和历史版本仍需要相应工具负责。

即使连接是你以前手工创建的，没有 FreePort 的历史记录，也属于发现与恢复的设计范围。外部创建、或可能被其他连接引用的目标，恢复后保留目标内容，避免影响其他使用者。

## 敢让你点下去，得先对数据负责

有些目录里是可以重新下载的文件，有些里面却有你的配置、会话和工作成果。你不敢随便点，是因为这些东西真的重要。

FreePort 的安全要求围绕这份顾虑制定：先看清、再执行，先校验、再清理；无法确认就保留数据，操作中断也要有据可查。

这些要求是产品必须通过的验收标准：

- **扫描只读。** 扫描不会触发迁移、恢复、删除或修复。
- **计划由你确认。** 候选不默认勾选，已有目标内容不静默合并或覆盖。
- **先复制、校验，再清理。** 内容与必要元数据验证完成前，不移除原始数据。
- **无法确认就停下。** 持续写入、身份变化、未知连接类型或校验失败时，保留数据并报告原因。
- **中断有据可查。** 根据事务记录和磁盘实际状态判断继续或回退；每个目录分别记录结果，部分完成如实显示。

跨盘迁移需要多个步骤。这些要求必须通过[投产验收](docs/requirements.md#8-投产验收)，才能开放真实用户数据迁移；它们是验收门槛，不能被写成「任何失败都能瞬间还原」的保证。

### 遇到被其他程序占用的目录

首版只检测并列出占用的程序和原因，由你自行关闭后重试；FreePort 不会结束进程，也不会关闭其他程序的文件句柄。“请求程序正常退出”和“强制关闭外部句柄”计划在后续版本中与提权一起提供，届时仍默认关闭、需你显式授权。

## 你可能还想知道

**是不是所有软件搬完都能用？**  
兼容性取决于软件本身、更新器、权限和目录内容。已知限制需要显示，不支持的情况必须阻塞。保留原路径是迁移方案，不能当作全软件兼容的保证。

**需要管理员权限吗？**  
MFT 快速扫描需要管理员权限，FreePort 会按需请求 UAC；拒绝后回退普通扫描。迁移用户目录通常不需要提权，缺少权限时会在改动数据前停止并说明。

**能有多快？**  
扫描器按 Windows NTFS MFT / USN 接口自主设计，无需第三方搜索客户端或服务。它加速的是目录发现，实际搬运和完整校验仍取决于数据量与磁盘速度。

**会上传我的文件吗？**  
扫描与文件操作在本机完成；产品设计不采集遥测，不设云服务，不上传文件内容。

**支持哪些磁盘？**  
首版面向本地 NTFS 卷中受支持的目录。网络路径和不支持的文件系统不在迁移范围内。目标盘须有足够空间，迁移后使用相关软件时也须保持可访问。
