# FreePort 需求

版本：1.0（以原始批处理为基准的精简版）
日期：2026-10-28
状态：首版目标为核心迁移/恢复投产可用。本文是范围与验收的权威依据；设计见[技术方案](technical-design.md)，搬运参数见[系统命令后端](system-command-backend.md)，当前进度见[实现状态](implementation-status.md)。

## 1. 核心目标

FreePort（CLI `fp`）把占空间的应用数据目录搬到别的盘，并在原路径留下目录 Junction，让应用无感继续使用原路径；需要时再把 Junction 恢复为真实目录。它是下面这段手工批处理的安全自动化版本：

```bat
mkdir D:\Dev\Cursor\data
robocopy "C:\Users\<user>\AppData\Roaming\Cursor" "D:\Dev\Cursor\data" /E /MOVE
rd /s /q "C:\Users\<user>\AppData\Roaming\Cursor"
mklink /J "C:\Users\<user>\AppData\Roaming\Cursor" "D:\Dev\Cursor\data"
```

批处理的风险是 FreePort 必须消除的问题：robocopy 因占用或权限跳过文件时，后续 `rd /s /q` 会把没搬走的数据直接删掉。FreePort 保持“搬运 → 清理源 → 建连接”的语义，但删除源之前必须先确认目标副本完整。

## 2. 首版范围

| 功能 | 首版要求 |
| --- | --- |
| 发现候选 | 选择盘符，扫描该盘用户目录（含 AppData）；自研 NTFS MFT/USN 快速枚举，不可用时回退普通只读遍历并说明原因；按 v2 知识库规则识别应用目录，用户也可手动添加目录 |
| 选择与目标 | 候选以目录树展示，默认不勾选；选择目标根目录（如 `D:\Dev`），可单项修改最终路径；显示体积、空间需求和冲突 |
| 迁移 | 每个目录一个独立事务：robocopy 复制到目标暂存 → 校验 → 收尾清理源 → `mklink /J` → 核验连接 |
| 恢复 | 选择 Junction 所在盘，发现所有目录 Junction / 目录符号链接（含手工创建、无历史记录的）；把真实目标当前内容复制回原路径，替换连接；真实目标默认保留 |
| 中断处理 | 依据落盘事务记录和实际文件对象，继续或回退到至少保留一份完整数据的状态 |
| 占用 | 检测并列出占用进程和原因，由用户自行关闭程序后重试；不自动结束进程、不关闭句柄 |
| 界面 | GUI 只有“迁移”和“恢复”两个入口；CLI 与 GUI 调用同一核心、同一检查 |

不做：缓存清理、软件卸载、注册表/环境变量修改、云同步、后台服务、定时任务、在线规则平台。

## 3. 支持对象

| 对象 | 约定 |
| --- | --- |
| 系统 | Windows 10 / 11 x64；不支持 Windows 7/8 |
| 源与目标 | 本地 NTFS 卷之间（含外接 NTFS 盘）；同卷搬迁允许但须提示“本卷净释放为 0” |
| 不支持 | FAT/exFAT/ReFS 作为迁移源或目标、UNC、映射网络盘、对外 SMB 共享目录 |
| 盘符 | 不写死盘符和用户名；写操作前用卷身份复核，盘符相同不代表同一盘 |
| 受保护位置 | 卷根、Windows、Program Files、整个用户主目录、整个 AppData、真实卷挂载点不能作为迁移根 |
| 已有连接 | 已是 Junction 的目录标为“已连接”并显示目标，不二次迁移；含内部连接的父目录不能整体迁移 |
| 特殊对象 | 未知重解析点、云占位符、外部共享硬链接、无法保留的 ADS/EFS：删除源之前阻塞 |

## 4. 迁移流程

| 步骤 | 要求 |
| --- | --- |
| 1. 预检 | 源/目标路径关系、卷身份、文件系统、可用空间、目标不存在（不合并、不覆盖）、占用、已有连接与特殊对象；写入事务记录 |
| 2. 复制 | robocopy `/E /COPY:DAT /XJ /SL` 到目标同卷暂存目录；返回码 ≥ 8 视为失败 |
| 3. 校验 | robocopy 返回码 ≥8 即失败；再比对文件/空目录全集、各数据流名称与大小、文件时间、只读属性、内部硬链接关系（只取目录与流列表和属性，不打开文件内容，不触发实时杀毒逐个扫描）；刷盘。不一致则保留源、停止。不做内容散列，与原批处理一致信任 robocopy；大小与时间都相同的静默损坏不在识别范围内 |
| 4. 切换与清理 | 暂存目录改名为最终目标；源改名为保留名；robocopy `/MOVE /IS /NOCOPY` 收尾；只按深度移除已确认身份的空目录。出现新文件、变更文件、未知对象即停止，不删 |
| 5. 建连接 | `mklink /J 原路径 目标`；核验连接指向和目标身份后标记完成 |

权限：目标继承目标父目录 ACL（与原批处理一致），确认前明示；不复制 owner/group/审计信息。

## 5. 恢复流程

1. 选择连接所在盘，扫描列出连接路径、目标、真实目标、体积、是否断链/循环/多处引用。
2. 用户多选并确认；空间不足提前阻塞，不先删连接腾空间。
3. 复制真实目标当前内容到连接旁暂存目录并校验 → 连接改保留名 → 暂存目录改回原路径 → 只移除旧连接条目。
4. 真实目标始终保留，不对其执行 `/MOVE` 或递归删除；多个连接指向同一目标时互不影响。
5. 断链、循环、无法访问、卷挂载点、未知 tag：可以列出，不能恢复，不自动删除连接。

## 6. 数据安全底线

| 编号 | 要求 |
| --- | --- |
| D01 | 扫描和预览只读，不能触发迁移、恢复或删除 |
| D02 | 删除任何源内容之前，目标已持久化并通过完整内容校验 |
| D03 | 每个事务落盘记录阶段；崩溃、断电、重启后能识别阶段并继续或回退，至少保留一份完整有效数据 |
| D04 | 写操作前复核卷身份、文件身份、路径关系、连接类型和真实目标；扫描结果只是线索 |
| D05 | 校验失败、命令失败、身份变化、未知重解析点、日志损坏：保留现场，停止危险操作 |
| D06 | 不使用无条件递归删除，不跟随连接删除真实目标，不删除新出现或无法确认的文件 |
| D07 | 单目录事务完成与整批完成分别记录，部分完成不能报告为全部成功 |
| D08 | 同一目录或事务不能被多个实例同时操作；重复点击不能重复执行 |
| D09 | 跨卷操作是可恢复事务，不宣称为操作系统级原子操作 |

## 7. CLI

```powershell
fp scan --volumes C: --mode migrate --out scan.json
fp plan --scan scan.json --select <id1,id2> --destination D:\Dev --out plan.json
fp apply --plan plan.json
fp scan --volumes C: --mode restore --out links.json
fp restore --scan links.json --select <id1,id2>
fp recover --transaction <id>
```

`apply`/`restore` 展示最终计划后确认；非交互执行须显式接受。旧扫描结果和外部输入在执行前重新预检。复杂树选择可用 `--selection` 文件。命令、参数、JSON 字段、退出码和事务 ID 保持稳定。

## 8. 投产验收

以下全部通过且有记录后，才能用于真实用户数据并发布稳定版。测试只使用专用测试目录或测试 VHDX。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| P01 | 跨卷迁移（普通桌面进程，非受限容器） | 内容、空目录、只读文件、ADS、时间一致；原路径为 Junction；应用可通过原路径读写 |
| P02 | 恢复（含手工 `mklink /J`、无 FreePort 历史） | 原路径变为真实目录，内容为迁移后的当前数据；真实目标保留 |
| P03 | 多连接共享同一目标 | 恢复其中一个不影响其他连接和目标 |
| P04 | 复制中文件被占用 / 权限拒绝 | robocopy 失败被识别，源完整保留，不进入清理 |
| P05 | 校验期间或收尾前源文件被修改、新增 | 检出差异，变化文件留在源，不被删除或覆盖 |
| P06 | 每个持久化边界强制终止进程 | 重启后 `recover` 能继续或回退，至少一份完整数据，重复执行不重复删除 |
| P07 | 目标已存在、目标盘空间不足、盘符漂移、拔盘 | 预检阻塞或安全停止，不静默覆盖 |
| P08 | 断链、循环、卷挂载点、未知 tag、外部硬链接、父子重叠选择 | 正确识别并阻塞，不误操作 |
| P09 | 批量中部分失败或取消 | 每项状态准确，整批不报成功 |
| P10 | 真实场景演练 | 先用可再生样本，再用 Cursor 这类真实应用目录完成迁移 → 使用 → 恢复全流程 |

已有用户验收结论（UAC 交互、断电）保留，不要求重复。原生测试中因 AppContainer 权限拒绝创建硬链接/Junction 夹具而失败的用例，须在普通桌面环境重跑通过，不能改为跳过。
