## 1. 产品目标与边界

FreePort 是一个 Windows 目录迁移与恢复工具，项目名 `freeport`，CLI 名称 `fp`。

用户选择磁盘，工具快速找出 AI 工具数据、模型、开发缓存、扩展及其他候选目录。用户多选并指定目标位置后，工具迁移真实内容，在原路径创建连接，让原软件继续使用原路径。恢复时同样先选盘，扫描盘上的目录连接，解析真实目标，经用户确认后把连接所在位置恢复为真实目录。

| 做什么 | 明确边界 |
| --- | --- |
| 扫描任意选定盘 | 不固定 C 盘源、不固定 D 盘目标、不写死用户名 |
| 提供迁移候选 | 规则匹配和未知隐藏目录发现；是否迁移由用户决定 |
| 多选目录并设置目标 | 默认可建议 `D:\Dev`，用户可以改为其他盘和目录 |
| 迁移并创建目录连接 | 保持原有访问路径；不修改软件配置和环境变量 |
| 扫描连接并恢复真实内容 | 包括手工创建的连接，不以 FreePort 记录作为发现前提 |
| 处理中断事务 | 依据日志和实际文件对象恢复，不猜测、不覆盖冲突内容 |

不做缓存清理、垃圾删除、软件卸载、注册表优化、云同步、常驻监控、定时任务或在线规则平台。占用处理只作为迁移/恢复前的可选开关，不做独立解锁工具。

## 2. 支持对象

### 2.1 磁盘与路径

| 对象 | 第一版约定 |
| --- | --- |
| C、D、E 等任意本地卷 | 均可选择作为扫描盘；可以多选 |
| 本地 NTFS 卷之间 | 正式迁移与恢复的主要支持范围，包括符合要求的外接 NTFS 盘 |
| 同一 NTFS 卷内目录搬迁 | 支持；可利用重命名优化，但必须显示“本卷净释放空间为 0” |
| FAT / exFAT / ReFS | 可以显示或只读扫描能力；第一版不执行无法保证连接与元数据语义的迁移，不静默改变处理方式 |
| 网络共享 | UNC 和映射网络盘不执行迁移/恢复；本地目录若作为业务 SMB 共享对外提供，也拒绝操作，避免远程写入 |
| 多用户目录 | 所选盘上按权限发现，不能只枚举当前 `%USERPROFILE%`；无权限项显式标明 |
| 盘符变化 | 用卷身份和文件身份复核；盘符相同不代表还是原来的盘 |
| 用户自选普通目录 | 可加入同一套预检与事务，不另设迁移机制 |

“任意盘”是盘符、卷和用户位置不受写死路径限制，不表示所有文件系统和系统目录都适合迁移。

### 2.2 候选目录规则

以下是规则覆盖范围。路径是识别线索，不能仅凭名字判定一定安全；全盘索引与环境变量、应用配置共同定位实际位置。

| 类别 | 覆盖内容 | 选择与处理原则 |
| --- | --- | --- |
| AI 工具 | Kimi / Kimi Code、Claude / Claude Code、DeepSeek / DSH、Grok、Grok Bot、Cursor、Codex 等 | 区分程序、配置、会话、下载与缓存；迁移前退出所属程序 |
| AI 模型 | Hugging Face、Torch、Ollama、ModelScope 等 | 识别环境变量与自定义目录；保留合法链接结构，不能把模型链接错误展开成多份 |
| C++ / MSVC | C++ IntelliSense、`.vs`、MSBuild、sccache / ccache 等 | 不把整个 Visual Studio、MSVC、Windows SDK 安装树当成普通缓存 |
| vcpkg | 二进制缓存、downloads、buildtrees、packages 等 | 识别真实根目录；识别内部及外部硬链接，不能破坏共享关系 |
| Go | build cache、module cache | 检查实际 GOCACHE / GOMODCACHE / GOPATH；保留只读属性 |
| Rust | Cargo registry / git、rustup 工具链、项目 target | 当前正在使用的工具链、编译任务和本工具自身目录需阻塞或排除 |
| 包管理器 | npm、pip、uv、pnpm、Bun、NuGet、Gradle 等 | 精确定位包缓存；不能把整个用户目录当作缓存 |
| 编辑器扩展 | VS Code、Cursor 扩展 | 与应用数据区分；保持原路径 |
| Obsidian | 各 vault 的 `.obsidian/plugins` | 从配置和所选盘发现 vault；不迁移笔记内容 |
| 企业微信 | WXWork 应用数据、文件及缓存 | 不顺带搬迁整个 Tencent 目录；保护聊天与附件数据 |
| 浏览器缓存 | Chrome、Edge、Firefox、Brave 等的实际缓存叶子目录 | 不把 Cookie、密码库和整个浏览器 profile 纳入“缓存” |
| 点开头目录 | `.claude`、`.dsh`、`.grok`、`.kimi-code` 以及其他未知 `.*` 目录 | 全部可以被发现；未知用途、凭据及系统性质目录不自动推荐 |
| 已存在连接 | Cursor、模型等已手动迁移的目录 | 标为“已连接”，展示真实目标，不二次迁移 |

保护清单优先于推荐清单。Windows、系统卷根目录、整个用户主目录、整个 AppData、安装器维护缓存、应用包管理目录及真实卷挂载点不能作为普通目录直接搬迁。

## 3. 核心流程

### 3.1 迁移向导

| 步骤 | 用户操作 | 界面必须展示 |
| --- | --- | --- |
| 1. 选择磁盘 | 选一个或多个源盘并扫描 | 容量、可用空间、文件系统、扫描后端和覆盖状态 |
| 2. 选择目录 | 搜索、排序、多选候选 | 所属应用、类别、源路径、体积、推荐理由、已有连接或阻塞原因 |
| 3. 设置目标 | 选择目标盘及根目录；必要时改某项最终目录 | 每项最终路径、空间需求、预计源卷释放量、冲突 |
| 4. 确认计划 | 确认条目和操作 | 源 → 目标映射、需关闭的程序、无法迁移项 |
| 5. 执行 | 查看进度，允许在安全点取消 | 当前目录、阶段、字节进度、速度、已完成/失败/待处理条目 |
| 6. 结果 | 查看完成或待处理现场 | 实际释放量、连接校验结果、中断恢复入口 |

候选项默认不勾选，推荐仅作为标记。候选以原生文件夹树展示，合格的最外层候选默认折叠；勾选父目录时子孙显示继承勾选，但只生成父根的一项事务，不能执行父子重叠任务。取消子树时祖先半选，父目录与其直属文件保留，只迁移其余完整选中的子目录；预览必须明确这一含义。受保护的导航祖先不能因此成为迁移根；已有迁移连接的父目录禁止整体迁移，提前说明原因。完整规则见[按需提权与目录树选择修订方案](elevation-and-selection.md)。已有目标不静默合并或覆盖，要求用户改目标。工具不强制结束进程。预检页提供独立的“请求占用程序正常退出”和“强制关闭外部文件/目录句柄”开关，全部默认关闭，具体规则见下文。

### 3.2 恢复向导——从盘发现，不从历史记录开始

默认扫描“连接条目所在的盘”。例如要把 C 盘的 Cursor 连接恢复成真实目录，就选择 C 盘；真实数据可以位于 D 盘、E 盘或其他受支持卷。

| 步骤 | 用户操作 | 工具行为 |
| --- | --- | --- |
| 1. 选择磁盘 | 选择要恢复的连接所在盘 | 全盘发现目录 junction 与目录 symbolic link，不要求有 FreePort 历史 |
| 2. 查看连接 | 多选需要恢复的项 | 展示连接路径、原始目标、解析后的真实目标、内容体积、空间需求、是否多处引用/断链/循环 |
| 3. 确认恢复 | 确认“是否将这些连接恢复为真实目录” | 明确恢复后的真实目录位置，以及原真实目标会保留还是清理 |
| 4. 执行恢复 | 查看进度 | 读取目标当前内容，复制校验，再替换连接；不恢复成迁移当天的旧快照 |
| 5. 结果 | 查看恢复结果 | 原连接位置现在为真实目录，内容和元数据验证完成 |

| 特殊情况 | 处理要求 |
| --- | --- |
| 手工创建、没有历史记录的连接 | 能恢复；不删除外部真实目标，避免影响其他软件或连接 |
| 多个连接指向同一目标 | 此处称为“多处引用”，不是 Windows 网络共享；每项明确展示，恢复一项时保留目标，不影响其他连接 |
| 目标在所选盘，连接在其他盘 | 不把真实目录误认作待恢复连接；需要扫描连接所在盘 |
| FreePort 创建且目标可证实为本事务独占 | 只有在恢复方案已说明、复制及校验完成后，才清理可证明安全的旧副本 |
| 无法证明目标独占 | 保留目标；恢复本身仍可成功，并明确剩余副本的位置 |
| 断链、循环、无法访问目标 | 可以列出，不能执行内容恢复；不自动删掉连接 |
| 系统兼容连接、卷挂载点、云占位符、未知 reparse tag | 不当作普通可恢复软连接；给出具体原因 |
| 恢复后磁盘空间不足 | 提前阻塞，不先删除连接来“腾位置” |

### 3.3 占用处理——强关句柄为首版必做功能

**必须自行实现外部文件/目录句柄的枚举、归属核验和强制关闭，不能仅以请求程序正常退出代替，不能调用 Unlocker、Handle、Process Explorer 或其他第三方解锁程序。** 使用 Windows 原生接口不属于第三方依赖。

Windows 的文件打开、共享模式、字节范围锁和内存映射可能造成不同的操作限制，不能把“曾被某进程使用”一律视为文件已锁死。

| GUI 开关 | 默认值 | 开启后的动作 |
| --- | --- | --- |
| 请求占用程序正常退出 | 关闭 | 使用 Restart Manager 请求已确认应用正常退出 |
| 强制关闭外部文件/目录句柄 | 关闭 | 显示风险警告，经用户启用后由自研模块关闭选中目录内匹配到的外部文件/目录句柄 |

两个开关独立：可以仅开启强关；两个都开启时先请求正常退出，再处理残留占用。所有其他可选操作开关同样默认关闭，新任务不自动继承上次启用状态。正常退出失败时，未启用强关就不能自动升级。

启用强关时警告一次，用户接受后对本次选定范围生效，不逐句柄反复确认。关闭或取消该提示时保持开关关闭。警告文案：

> 将强制关闭其他程序的文件/目录句柄，可能导致程序崩溃、未保存数据丢失或文件损坏。仅处理本次选中目录。FreePort 仍会完整复制和校验，但无法撤销对外部程序的影响。

| 情况 | 行为 |
| --- | --- |
| 两个开关均关闭 | 只列出占用和原因，由用户自行释放后重试 |
| 仅开启正常退出 | 尝试正常退出；失败则暂停相关项，不强关句柄 |
| 仅开启强关 | 完成风险提示后直接进入自研句柄枚举、匹配和关闭流程 |
| 两个开关都开启 | 先正常退出，再对仍占用且已匹配本次范围的句柄执行强关 |
| 释放完成 | 重新执行访问能力、对象身份、内容变化和稳定性预检，通过后继续 |
| 保护进程、权限不足、对象无法核验、系统关键对象 | 明确报告无法关闭的原因，不扩大到整进程强杀、系统对象或未知句柄 |
| 句柄关闭调用结果不确定 | 重新枚举并核验，不按旧句柄数值盲目重复关闭 |
| 程序重开句柄或继续通过映射写入 | 有限重扫和重试；仍不能稳定时保留现场，不能跳过校验 |

强关只针对经核验的本地磁盘文件/目录句柄，不能顺带关闭进程、线程、令牌、互斥量、管道、设备、网络连接或其他目录的句柄。GUI 开关和 CLI 显式参数都必须进入同一个核心模块。

强制关闭外部句柄是有风险的用户选项，不等于获得运行中应用的一致性快照；对外部应用未保存缓冲、内存映射及状态的影响不可回滚。文件迁移/恢复仍保持完整的复制、持久化、散列、元数据和事务检查，不能将“句柄已关闭”视为“数据已完整持久化”或承诺操作必定不中断。

## 4. 数据与事务要求

FreePort 搬运与清理的数据完整性优先于节省空间和速度。无法确认时，允许保留两份副本或残留现场，不能删除唯一有效数据。用户显式启用强关外部句柄时，外部应用的未保存状态风险按上述警告处理，不能冒称迁移事务可以撤销这些影响。

| 编号 | 必须满足的要求 |
| --- | --- |
| D01 | 扫描和预览阶段对用户目录只读 |
| D02 | 删除任何原始内容之前，目标内容已持久化，并完成完整内容及必要元数据验证 |
| D03 | 迁移和恢复都使用落盘事务记录；程序崩溃或电脑重启后能识别中断阶段 |
| D04 | 写操作前复核卷身份、文件身份、路径关系、连接类型和真实目标，防止盘符漂移与路径替换 |
| D05 | 先按用户选择执行占用释放；之后仍有阻塞、持续写入或无法建立稳定校验边界的目录拒绝切换，不以“已检查进程名”或“已关闭句柄”替代安全检查 |
| D06 | 散列不匹配、文件增删、流变化或系统命令失败时保留现场，不继续删除源；新事务不强制复制 owner/group |
| D07 | 删除只针对事务拥有且重新核验的对象，不递归跨越连接，不删除新出现或无法确认的文件 |
| D08 | 同一条目录迁移或恢复构成独立事务；批次记录每项状态，中断后不能把部分成功报成全部成功 |
| D09 | 多个程序实例不能同时操作相同目录或同一事务；双击按钮不能重复执行 |
| D10 | 恢复外部连接不依赖 FreePort 的历史；需要在执行前为本次恢复建立新的事务 |
| D11 | 特殊链接、ADS、EFS 等无法保留时须在删除前阻塞；普通目标的 ACL/owner 按原批处理继承目标权限，不要求全量复刻 |
| D12 | 不能承诺跨盘多个目录的操作系统级原子提交；通过日志、校验、分阶段切换和可恢复现场确保一致性 |
| D13 | 强关句柄前记录范围、进程身份、句柄与文件身份及操作意图；记录结果，重启后不按旧句柄编号重放，不将外部副作用伪称可回滚 |

## 5. 高性能要求

### 5.1 两层扫描

1. **快速发现**：扫描器自主实现，直接使用 Windows 支持的 NTFS MFT / USN 元数据枚举，快速获得文件名、目录结构和候选连接线索；不以逐层递归全盘为主路径，不依赖第三方搜索 SDK、IPC、客户端或索引服务。USN/MFT 仅承担快速发现，不承担跨盘搬运或内容校验。
2. **精确核验**：只对命中候选和用户选中项读取更多元数据、真实连接信息、实际大小与内容；执行前再次核验。

快速名单、精确体积、完整内容校验是不同阶段。不能为显示精确目录大小而阻塞首屏；大小未知时显示“统计中/未知”，不能显示为 0。权限不足、元数据枚举不完整或降级枚举的范围必须说明。

### 5.2 待验收性能目标

| 场景 | 目标，不作为未测试的承诺 |
| --- | --- |
| 首次自研 NTFS 元数据枚举 | 100 万条名称记录的参考 NVMe、管理员权限环境下，最终候选清单目标 P95 ≤ 10 秒；首屏候选流式出现，目标 ≤ 2 秒 |
| 同次运行中重复扫描，已有内存名称快照 | 用 USN 增量刷新后重新匹配，目标 P95 ≤ 2 秒；journal 不连续则重新全量枚举 |
| 精确体积 | 异步更新，不阻塞选择和界面；必须标出来源与完整性 |
| 迁移吞吐 | 在相同内容、磁盘和权限语义条件下，对比 CopyFile2 / Robocopy；完整校验耗时单列 |
| 界面响应 | 扫描、复制、校验在后台工作线程执行，操作反馈目标 ≤ 100 ms |
| 内存与句柄 | 分页、流式处理、有界并发；不能按全盘文件数创建线程或无限持有句柄 |

扫描加速以名称发现为目标；跨盘传输和内容校验按各自阶段测量。性能优化不能以跳过校验、吞掉错误或改变数据语义为代价。

## 6. 最小界面与 CLI

GUI 只设“迁移”和“恢复”两个入口，复用选盘、结果多选、预览、执行和结果页。中断事务提示属于这两个操作的恢复机制，不单独扩展成管理平台。

CLI 与 GUI 必须调用同一核心，不允许 CLI 缺少 GUI 的校验。拟定命令如下，最终参数在实现时保持精简：

```powershell
fp scan --volumes C: E: --mode migrate --out scan.json
fp scan --volumes C: --mode restore --out links.json
fp plan --scan scan.json --select <id1,id2> --destination D:\Dev --out plan.json
fp apply --plan plan.json
fp restore --scan links.json --select <id1,id2>
fp recover --transaction <id>
```

占用处理参数为 `--request-app-exit` 和 `--force-close-handles`，默认均关闭。显式传入强关参数视为授权对本次选中目录执行强关，执行前向终端输出同样的风险警告；不得从旧配置自动打开。

`apply` 和 `restore` 展示最终计划后确认；非交互执行需显式接受该计划。扫描结果文件不是可直接执行的可信指令，旧结果与外部输入必须重新预检。

### 6.1 首批多语言与自动适配

CLI 与 GUI 首版同步支持以下六种语言；这里的语言范围包括操作界面，不仅是 README 翻译。

| 语言 | 资源标识 | 语言选择器显示名称 | 自动模式匹配的 Windows 国家/地区代码 |
| --- | --- | --- | --- |
| 简体中文 | `zh-CN` | 简体中文 | `CN` |
| 英文 | `en` | English | 其他国家/地区，以及无法读取或无法匹配时 |
| 繁体中文 | `zh-TW` | 繁體中文 | `TW`、`HK`、`MO` |
| 日文 | `ja` | 日本語 | `JP` |
| 韩文 | `ko` | 한국어 | `KR` |
| 德语 | `de` | Deutsch | `DE`、`AT`、`LI` |

自动模式读取当前 Windows 用户的“国家或地区”设置。这是本机设置，不保证等于用户的实际所在地或偏好语言；不通过 IP、定位、时区、键盘或联网服务推断。未列入映射的地区统一英文，例如新加坡、瑞士；用户仍能手动选择六种语言中的任意一种。

语言选择规则：

1. CLI 本次显式 `--lang <语言标识>` 优先；`--lang auto` 强制本次按系统地区选择，忽略已保存的手动偏好，不修改该偏好。
2. 未提供本次参数时，使用已保存的用户语言选择；GUI 提供“跟随系统地区（自动）”和六种语言，手动选择后保存为 CLI / GUI 共用偏好。
3. 首次使用或已选自动模式时，按上述地区映射；读取失败、空值、未知地区或未覆盖地区均回退 `en`。
4. 手动指定非法语言标识时，用英文说明可选值并拒绝本次命令，不进入文件操作。已保存偏好无效时回退英文并提示重新选择。

语言名称始终使用表中的自称，方便用户从不熟悉的界面切换。GUI 空闲时切换后刷新界面；执行期间禁止切换，任务结束后恢复可选。CLI 在启动时确定本次语言，同一操作的风险说明与确认使用同一语言。语言选择与操作授权独立，不能启用占用处理、扩大选中范围或绕过检查。

| 本地化范围 | 要求 |
| --- | --- |
| GUI | 窗口、按钮、菜单、列名、状态、说明、预览、占用提示、取消和结果均翻译 |
| CLI | 帮助、参数错误、交互提示、进度、失败原因、结果摘要均翻译 |
| 安全提示 | 迁移、恢复和强关风险在六种语言中语义一致；强关提示完整保留崩溃、未保存内容丢失、文件损坏及外部副作用无法撤销的说明 |
| 规则与核心消息 | 分类、推荐理由、阻塞原因和错误使用稳定标识关联翻译，不把源语言句子作为程序判断依据 |
| 脚本与日志 | 命令、参数、确认令牌 `yes`、退出码、JSON 字段与机器枚举、规则 ID、事务 ID 保持稳定；人类可读消息可翻译，不影响重放或恢复 |
| 文本与路径 | 支持中日韩和德语字符、长文本与显示缩放；翻译只影响显示，实际路径和文件身份无损传递 |
| 资源与回退 | 六语资源随程序离线提供，GUI / CLI 共用；运行时缺词条回退内置英文，禁止显示空白风险提示；正式发布前六语词条及参数必须完整 |

`--lang` 与六套离线资源已实现；端到端覆盖和数据安全门槛见 [实现与验证状态](implementation-status.md)。

### 6.2 按需提权与层级选择

普通权限启动；在所选卷快扫或明确写操作实际缺少能力时，提供 UAC 授权入口，保留选择、目标、发起用户与语言上下文。提权不代替强关授权，不承诺管理员能操作所有对象。拒绝授权不改变用户数据，快扫允许明确选择普通枚举；实际后端、回退原因和覆盖不足即时展示。

CLI / GUI 共用层级选择、排除、任务归并、预检和执行核心；简单 CLI 继续使用 `--select`，复杂树选择使用 `--selection` 文件，按需提权使用显式 `--elevate`，已接入 0.1.1-dev.1 开发构建；实际 UAC 交互验收尚未完成，具体语义、兼容要求及边界测试见[修订方案](elevation-and-selection.md)。不扩展删除或终止进程功能。
